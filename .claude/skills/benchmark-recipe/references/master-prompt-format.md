# 마스터 복제 프롬프트 작성 형식 (`MASTER_REPLICATION_PROMPT.md`)

`BENCHMARK_RECIPE.md`가 **기능별로 흩어진 2-프롬프트 모음**이라면, `MASTER_REPLICATION_PROMPT.md`는 그것을 **하나의 자기완결 빌드 지시서**로 합친 것이다. 목적: 이 문서 **한 장만** 다른 컴퓨터/AI 코딩 도구에 던지면, 분석한 사이트의 디자인·정보구조·인터랙션·콘텐츠 밀도를 **복제에 가까운 수준**으로 재현하는 새 사이트를 만들 수 있게 한다(원본 이미지·문장·고유 신원은 법적 안전을 위해 제외).

## BENCHMARK_RECIPE.md와의 차이 (왜 둘 다 만드는가)

| | BENCHMARK_RECIPE.md | MASTER_REPLICATION_PROMPT.md |
|---|---|---|
| 단위 | 기능 1개 = 레시피 1개 | 사이트 전체 = 프롬프트 1장 |
| 의존성 | 로컬 분석 파일 맥락 일부 전제 | **자기완결** — 외부 파일 참조 없이 단독 동작 |
| 수신자 | 특정 컴포넌트를 복제하려는 개발/디자인 | 사이트 전체를 새로 빌드하려는 AI 팀 |
| 신원/저작권 | 원본 경로·실재 콘텐츠 그대로 인용 | **가상화·재작성**(병원명·인물·이미지·문장 안전 치환) |

레시피는 "부품 도면", 마스터는 "완성차 제작 지시서 + 안전 규정"이다. 마스터는 레시피 13종을 빠짐없이 흡수해야 한다.

## 필수 골격 (이 순서로 작성)

문서 본문은 **하나의 ` ```md ` 코드블록**(=최종 프롬프트)으로 감싸 그대로 복붙 가능하게 하고, 그 앞에 목적/사용법 안내, 뒤에 검수 프롬프트·이미지 생성 프롬프트를 둔다.

1. **문서 머리말** — 목적, "이 문서만 전달하면 됨" 사용법.
2. **최종 프롬프트(코드블록 시작)**
   - **빌드 오케스트레이터 선언 + 법적/윤리 안전 규칙**(이미지·문장·신원 비도용, 과장표현 금지).
   - **구현할 사이트 콘셉트** — 가상 브랜드명, 브랜드 성격, 핵심 톤, 금지 톤. (design_findings의 톤을 가상 브랜드로 옮김)
   - **기술 목표** — 반드시 동작할 기능 목록(아래 §레시피 매핑 전수) + 라이브러리 원칙.
   - **빌드 에이전트 구성(역할별 분담)** — 아래 [멀티 에이전트 역할 가이드](#멀티-에이전트-역할-가이드) 표를 반드시 포함.
   - **디자인 시스템** — design_findings의 실재 토큰을 CSS 변수로(이름은 의미형으로 재명명 가능), 타이포·컬러 사용 규칙, 토큰 외 보조색 처리.
   - **AI 이미지 생성 지시** — 원본 이미지 대체용 생성 프롬프트(인물 비식별·로고/텍스트 없음).
   - **콘텐츠 재작성 원칙** — 톤, 금지 표현, 문장 재작성 방식, 고유정보 가상 치환.
   - **정보 구조(라우트)** — content_findings IA 기반. **모달 전용 콘텐츠는 독립 라우트로도 발행**(08-renewal-insights 1순위 흡수).
   - **전역 레이아웃** — Header/GNB/모바일 드로어/**sticky 예약·전화 CTA**(전환 누수 보완)/Footer(데모 면책 문구).
   - **메인 페이지 구성** — hero→trust strip→진료 카드→캐러셀→스크롤 시퀀스→STEP→의료진→오시는길.
   - **풀스크린 모달 시스템** — 공통 컴포넌트 + 과목별 콘텐츠 + **접근성(role=dialog·focus trap·ESC·scroll lock·focus return)** 명시.
   - **주요 컴포넌트 상세** — 레시피 1·4·5·6·11·9·12·13을 컴포넌트 명세로(아래 매핑 참조).
   - **페이지별 콘텐츠 방향** — 라우트별 섹션.
   - **접근성 기준 / 성능 기준 / SEO 기준 / 분석·전환 측정(GA4)**.
   - **구현 완료 기준 / 구현 순서**.
   - (코드블록 끝)
3. **검수 프롬프트(별도 코드블록)** — 구현 결과를 ⑤ QA 역할로 점검하는 체크리스트.
4. **이미지 생성 프롬프트 모음(별도 코드블록)** — 바로 이미지 도구에 넣을 영문 프롬프트.

## 멀티 에이전트 역할 가이드 (마스터 프롬프트에 반드시 포함)

마스터 프롬프트는 단일 "너는 개발자다"가 아니라, 수신 AI가 **역할별 전문 작업으로 분담**하도록 설계한다. 아래 표를 프롬프트에 그대로 넣는다(사이트 도메인에 맞게 책임/참조 절만 조정).

| 역할(에이전트) | 책임 | 주로 참조할 절 | 담당 산출물 |
|---|---|---|---|
| ① 프론트엔드 아키텍트 | 라우팅·빌드 셋업·전역 레이아웃·반응형 골격·컴포넌트 파일 구조 | 정보 구조 / 전역 레이아웃 / 구현 순서 | 라우터, Header·Footer·sticky CTA, 페이지 셸 |
| ② 디자인 시스템 엔지니어 | CSS 변수 토큰·타이포·간격·그림자·테마, 컴포넌트 비주얼 | 디자인 시스템 / 주요 컴포넌트 상세 | tokens.css, 공통 UI·컴포넌트 스타일 |
| ③ 인터랙션/애니메이션 엔지니어 | 캐러셀·스크롤 시퀀스·모달·탭·아코디언·타이머·자가진단 동작·모션 | 주요 컴포넌트 상세 / 풀스크린 모달 시스템 | Vanilla JS 컴포넌트, 모션, 모달 a11y |
| ④ (도메인) 콘텐츠 에디터 | 모든 한글 카피 재작성, 가상 신원·면책, Q&A·설명 | 콘텐츠 재작성 원칙 / 페이지별 콘텐츠 방향 | 페이지·모달 텍스트, 면책 문구 |
| ⑤ 접근성·SEO·성능 QA | 키보드·focus trap·aria·색대비·메타·구조화데이터·성능 예산 | 접근성/SEO/성능 기준 / 검수 프롬프트 | 검수 리포트, 수정 지시 |

핸드오프 규칙(반드시 명시):
- ②가 토큰 먼저 확정 → ①③은 CSS 변수만 사용(HEX 하드코딩 금지).
- ③ 컴포넌트는 ④의 실제 한글 콘텐츠로 채움(로렘입숨 금지).
- ⑤는 각 역할 산출 직후 점진 검증(모달 a11y·모바일 375px 우선).
- 역할 충돌은 "성능·접근성 기준"을 상위 규칙으로 조정.

## 원본 약점 → 마스터에서 선제 보완 (08-renewal-insights 흡수)

- **모달에만 갇힌 콘텐츠 → SEO/딥링크 손실**: 모달 콘텐츠를 독립 라우트로도 발행 + SSR/progressive enhancement.
- **홈 전환 누수**: 전역 sticky 예약/전화 CTA를 기본 탑재.
- **모달 접근성 미검증**: role=dialog·focus trap·ESC·scroll lock·focus return을 처음부터 구현.
- **데드코드/번들 낭비**(라이브 검증 시): jQuery·미사용 라이브러리(rellax/simpleParallax 등) 금지, 폰트 3계열 이하.
- **이미지 비최적**: WebP/AVIF + lazy-load 기본값.

## 안전(법적) 치환 규칙

원본을 "복제에 가깝게" 하되 아래는 반드시 가상화·재작성한다(그대로 쓰면 안 됨):
- 이미지/사진/로고/아이콘 → AI 생성 또는 저작권 안전 대체.
- 문장 → 같은 정보 밀도로 새로 작성(원문 복붙 금지).
- 병원명·실명·주소·전화·수술건수·논문·저서 → 가상/더미/정성 표현.
- 푸터에 "데모용 예시이며 실제 의료기관 정보가 아님" 면책 명시.
