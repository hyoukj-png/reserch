# 벤치마킹 레시피 작성 형식

`BENCHMARK_RECIPE.md`의 각 항목을 작성하는 표준 형식과 프롬프트 품질 기준. 레시피의 목적은 **다른 프로젝트의 AI에게 그대로 던지면 해당 기능이 재현되는** 실행 가능한 명령어를 제공하는 것이다.

## 전체 문서 구조

```markdown
# 벤치마킹 레시피 — {사이트명}

> 이 사이트의 핵심 기술/패턴을 다른 프로젝트에서 복제하기 위한 가이드.
> 각 레시피의 프롬프트는 AI 코딩 도구에 그대로 붙여넣어 사용한다.

## 한눈에 보기: 기술-페이지 매핑
{표}

## 레시피 1: {기능명}
## 레시피 2: {기능명}
...

## 적용 팁
{여러 레시피를 조합할 때의 순서·주의점}
```

## 기술-페이지 매핑 표

```markdown
| # | 핵심 기능 | 사용 기술 | 원본 경로 | 복제 가치 | 난이도 |
|---|----------|----------|----------|----------|--------|
| 1 | 히어로 캐러셀 | Swiper.js | `/` | 높음 | 보통 |
| 2 | 제품 필터 그리드 | CSS Grid + JS | `/products` | 높음 | 쉬움 |
```

- **원본 경로는 반드시 pages.json에 실재하는 URL.** 환각 경로는 QA에서 blocker로 잡힌다.
- **복제 가치**: 그 사이트를 특별하게 만드는 정도. 흔한 기능은 낮음, 차별화 기능은 높음.

## 개별 레시피 블록 (2-프롬프트 구조)

각 레시피는 **수신자가 다른 두 개의 프롬프트**로 나눈다. 하나는 화면을 설계하는 시니어 디자이너용, 하나는 동작을 구현하는 전문 개발자용이다. 이렇게 나누는 이유: 디자이너는 "무슨 콘텐츠를 어떤 위계로 배치하고 어떤 인상을 줄지"가 필요하고, 개발자는 "그 화면을 어떤 라이브러리·트리거·타이밍으로 살아 움직이게 할지"가 필요하다. 한 프롬프트에 둘을 섞으면 양쪽 모두에게 불완전해진다.

```markdown
### 레시피 N: {기능명}

**무엇을:** {한 문장으로 복제 대상 기능 설명}
**어디서:** {pages.json 실재 경로} — {그 페이지에서 어떻게 보이는지}
**사용 기술:** {라이브러리/기법}

#### 🎨 디자인 프롬프트 (시니어 디자이너용)
> 시안·화면설계를 만드는 디자이너에게 전달. 섹션을 카테고리로 나누고, 각 카테고리에 들어갈 **실제 한글 콘텐츠**와 위계·톤, 그리고 어디에 어떤 인터랙션이 얹히는지(디자이너 관점)를 서술한다.
```
{디자인 프롬프트}
```

#### ⚙️ 인터랙션/개발 프롬프트 (전문 개발자용)
> 퍼블리셔·프론트엔드 개발자에게 전달. 라이브러리·트리거·타이밍·이징·반응형 분기·접근성 구현 명세.
```
{개발 프롬프트}
```

**구현 노트:** {의존성, 주의점, 대안 라이브러리}
```

## 디자인 프롬프트 품질 기준 (시니어 디자이너용)

디자이너는 "코드"가 아니라 "무엇을 어떻게 보여줄지"를 받아야 한다. 다음을 모두 담는다:

1. **카테고리(섹션) 분해** — 이 컴포넌트/섹션을 구성하는 영역을 명시적으로 나눈다. 예: `① 섹션 헤드 ② 단계 카드 3개 ③ 하단 CTA`. 디자이너가 화면을 영역 단위로 잡을 수 있게.
2. **카테고리별 한글 콘텐츠** — 각 영역에 **실제 한글 카피·항목**을 예시로 채운다. 플레이스홀더("제목 들어감")가 아니라 "백내장은 노화로 수정체가 혼탁해지는 질환입니다" 수준의 진짜 한글 문장/라벨. **모든 콘텐츠는 한글로 설계하도록 명시한다**(영문 카피 금지, 단 브랜드명·기술용어 예외).
3. **위계·레이아웃** — 무엇이 가장 크고 먼저 읽히는지, 컬럼 수, 정렬, 여백 밀도. design_findings 토큰(컬러·폰트) 연결.
4. **인터랙션의 위치와 인상** — 개발 명세가 아니라 디자이너가 알아야 할 "이 카드는 스크롤하면 아래에서 순차로 떠오른다", "활성 단계는 골드로 채워진다" 수준의 행동 묘사. 어느 요소에 모션이 붙는지를 시안에 반영할 수 있게.
5. **톤·금지사항** — 브랜드 톤(예: 차분한 럭셔리), 피해야 할 표현(공포 마케팅, 차가운 블루 등).

## 개발 프롬프트 품질 기준 (전문 개발자용)

개발자는 그대로 구현 가능한 기술 명세를 받아야 한다:

1. **라이브러리·버전·모듈** — 예: "Swiper.js v11, 모듈 Navigation/Pagination/Autoplay/A11y"
2. **트리거·타이밍·이징** — duration, delay, easing, scrub, autoplay 간격, stagger 등 수치
3. **반응형 분기** — breakpoint별 동작 차이(slidesPerView, pin 해제 등)
4. **스타일 토큰 연결** — 인디케이터·CTA 색을 design_findings 실제 변수(`--sub-2` #FDC436)로
5. **접근성** — aria 속성, 키보드 동작, `prefers-reduced-motion` 폴백
6. **완료 기준** — 동작 검증 조건

## 좋은 예 (2-프롬프트)

**🎨 디자인 프롬프트 — STEP 번호형 프로세스**
```
"백내장 수술 절차" STEP 섹션을 디자인해줘. 모든 콘텐츠는 한글로 설계.
[카테고리 구성]
① 섹션 헤드: 소제목 "안심 수술 프로세스" + 본문 "정밀 계측부터 사후관리까지, 4단계로 안내합니다"
② STEP 카드 4개 (각 카드 = 큰 번호 + 단계명 + 2줄 설명):
   - STEP 01 정밀 계측 — "최신 장비로 안구를 0.01mm 단위까지 측정합니다"
   - STEP 02 맞춤 렌즈 선택 — "생활 패턴에 맞춰 인공수정체를 함께 결정합니다"
   - STEP 03 무봉합 수술 — "10분 내외, 통증과 회복 부담을 최소화합니다"
   - STEP 04 사후관리 — "수술 다음 날부터 정기 검진으로 경과를 관리합니다"
③ 하단 CTA: "수술 상담 예약하기"
[위계·톤] 번호가 가장 크게(시선 유도), 단계명은 세리프 헤드라인, 설명은 본문 산세리프. 베이지 배경에 아이보리 카드, 번호와 CTA는 골드. 차분한 럭셔리 톤, 의료 불안을 줄이는 안심 카피.
[인터랙션 위치] 스크롤로 섹션 진입 시 4개 카드가 좌→우 순서로 하나씩 떠오르며 등장. 카드 위 마우스를 올리면 살짝 떠오름.
```

**⚙️ 인터랙션/개발 프롬프트 — STEP 번호형 프로세스**
```
위 STEP 섹션의 동작을 구현해줘.
- 레이아웃: 데스크탑 CSS Grid 4열, 태블릿 2열, 모바일(<768px) 1열 세로 스택
- 번호 "01~04" Playfair Display, 색 골드 #FDC436(--sub-2); 단계명 Noto Serif KR #6A5643(--pri-2); 설명 Pretendard Variable
- 카드 배경 #FFFBF3(--pri-4), 라운드 12px; 호버 시 translateY(-6px) + 그림자, transition 200ms ease-out
- 카드 사이 연결선: ::after 가상요소, 색 #B8A47F(--pri-3), 마지막 카드만 숨김(데스크탑만)
- 진입 애니메이션: AOS data-aos="fade-up", 카드별 data-aos-delay 0/100/200/300(stagger), duration 600, once:true
- 마크업: <ol>+<li>로 단계 의미 부여, prefers-reduced-motion이면 애니메이션 비활성·즉시 표시
완료 기준: 데스크탑 4열+연결선, 모바일 1열, 순차 등장, 호버 부양, 모션 감소 폴백이 모두 동작.
```

디자인 프롬프트는 **한글 콘텐츠를 실제로 채우고 카테고리를 나눈** 반면, 개발 프롬프트는 **수치·토큰·접근성**을 담았다. 두 프롬프트의 토큰(#FDC436)과 기능 묘사가 서로 호응해야 한 화면으로 합쳐진다.
