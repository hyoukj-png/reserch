# PRD 작성 형식 (리뉴얼 제작 PRD)

`PRD.md`는 분석 결과를 **"우리가 새로 만들 사이트"의 페이지 제작 요구사항 정의서**로 번역한 산출물이다. BENCHMARK_RECIPE/MASTER_REPLICATION_PROMPT가 *AI가 복제하도록* 쓴 프롬프트라면, PRD는 *사람(기획/디자인/개발)이 읽고 제작 범위를 합의·착수*하기 위한 문서다.

## 무엇이 다른가 (다른 산출물과의 경계)

| 산출물 | 독자 | 성격 |
|--------|------|------|
| `08-renewal-insights.md` | 의사결정자 | 유지/개선/도입 + 우선순위 (왜) |
| `BENCHMARK_RECIPE.md` | AI 코딩도구 | 기능별 복제 프롬프트 (어떻게-부품) |
| `MASTER_REPLICATION_PROMPT.md` | 수신 AI | 사이트 전체 한 장 빌드 지시 (어떻게-전체) |
| **`PRD.md`** | **기획·디자인·개발** | **페이지별 제작 요구사항 + 범위·성공기준 (무엇을 만든다)** |

PRD는 `08`의 개선 방향을 **반영**하여 "있는 그대로 복제"가 아니라 "리뉴얼된 우리 사이트"를 페이지 단위로 정의한다. 단, 모든 페이지 목록·섹션·콘텐츠는 수집 원본(pages.json / content_findings)에 근거해야 하며 환각 페이지를 만들지 않는다.

## 입력 (모두 교차)

- `_workspace/content_findings.md` — 페이지 목록·IA·페이지별 콘텐츠·CTA (페이지 맵의 1차 근거)
- `_workspace/design_findings.md` + `10-design-tokens-structured.md` — 공통 컴포넌트·토큰
- `_workspace/tech_findings.md` — 페이지별 인터랙션·기술·성능 (기능 요구사항·성공기준)
- `08-renewal-insights.md` — 유지/개선/도입 → 페이지별 "개선 반영"과 우선순위·범위(MVP)
- `pages.json` — 페이지 경로 실재성 검증

## 전체 문서 구조

```markdown
# PRD — {사이트명} 리뉴얼

> 본 문서는 분석 대상 사이트를 벤치마킹하여 리뉴얼 제작하기 위한 제품 요구사항 정의서다.
> 페이지 목록·섹션 구성은 원본(pages.json) 근거, 개선 방향은 08-renewal-insights 반영.

## 1. 개요 / 목표
- 프로젝트 배경 (한 줄), 리뉴얼 목표 2~4개
- 타깃 사용자 / 핵심 사용자 시나리오
- 사이트 정체성 한 문장 (08과 동일 앵커)

## 2. 페이지 맵 (우선순위)
| 우선순위 | 페이지 | 경로(원본) | 한 줄 목적 | 비고(신규/개선/유지) |
|---------|--------|-----------|-----------|------------------|
| P0 | 홈 | / | ... | 개선 |
- P0=MVP 필수, P1=후속, P2=선택. 우선순위는 08의 임팩트×난이도와 정합.

## 3. 페이지별 요구사항
각 P0~P1 페이지마다 아래 블록을 반복:
### 3.x {페이지명} ({경로})
- **목적:** 이 페이지가 달성할 것
- **섹션 구성:** 위→아래 섹션 순서 (원본 근거)
- **컴포넌트:** 사용할 공통/개별 컴포넌트 (4. 참조)
- **핵심 콘텐츠(한글):** 실제 한글 카피·헤드라인·항목 (플레이스홀더 금지)
- **CTA:** 위치·문구·목적지
- **인터랙션:** 동작·트리거 (5. 참조)
- **⚠️ 개선 반영:** 08에서 가져온 이 페이지의 개선점 (있으면)

## 4. 공통 컴포넌트 & 디자인 토큰
- 글로벌 헤더/푸터/버튼/카드 등 재사용 컴포넌트 명세 (05-components 근거)
- 디자인 토큰: 정확값은 `tokens/tokens.dtcg.json`(또는 tailwind/css) 참조. 핵심 컬러·타입·간격 스케일 요약.

## 5. 기능 요구사항 (인터랙션)
| 기능 | 적용 페이지 | 라이브러리/방식 | 동작 명세 | 반응형 | 접근성 |
- tech_findings의 기술→페이지 매핑 기반. "로드만 됨/데드코드"는 제외.

## 6. 우선순위 · 범위 (MVP)
- MVP(P0) 범위 / 후속(P1·P2) 범위 표
- 임팩트×난이도 정렬 (08과 정합), 빠른 성과 상단

## 7. 성공기준 / QA 체크
- 성능 목표 (예: 모바일 LCP < 2.5s — 07 근거)
- 접근성 목표 (WCAG AA 대비 — 10 근거)
- 페이지별 완료 정의(DoD) 체크리스트
```

## 품질 기준

- **페이지·경로는 pages.json 실재값만.** 새 페이지를 제안하려면 반드시 "신규(08 도입 근거)"로 표시하고 근거를 단다.
- **콘텐츠는 실제 한글로.** "여기에 소개 문구" 같은 플레이스홀더 금지 — content_findings의 실제 카피를 옮기거나 톤에 맞게 작성.
- **개선 반영은 08에서만.** PRD가 임의로 개선을 발명하지 않는다. 08의 개선/도입 항목을 해당 페이지에 연결.
- **요구사항은 검증 가능하게.** 성공기준은 수치/체크 가능한 형태(LCP 초, 대비비, DoD 항목)로.
- **한국어 + 기술용어 영문** (프로젝트 규약).

## 자가 점검

- [ ] 페이지 맵의 모든 경로가 pages.json에 실재하는가 (신규는 명시)?
- [ ] 각 P0 페이지에 목적·섹션·컴포넌트·한글 콘텐츠·CTA·인터랙션이 모두 채워졌는가?
- [ ] 우선순위(P0~P2)가 08의 임팩트×난이도와 모순되지 않는가?
- [ ] "개선 반영" 항목이 08에 실재하는 항목과 연결되는가?
- [ ] 성공기준이 수치/체크 가능한가?
- [ ] 플레이스홀더가 남아 있지 않은가?
