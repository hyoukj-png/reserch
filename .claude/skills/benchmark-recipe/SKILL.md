# 벤치마킹 레시피 & 통합 리포트 작성

세 분석가의 발견을 종합하여 사용자에게 전달되는 최종 산출물 4종을 작성한다. 이 하네스의 부가가치가 집약되는 단계다.

## 왜 이렇게 하는가

세 영역의 발견이 따로 있으면 "정보"일 뿐이다. 이것을 교차시켜 **사이트의 정체성을 정의**하고, 그 위에서 **"이 기능을 내 프로젝트에서 이렇게 복제하라"는 실행 가능한 레시피**로 바꿔야 비로소 의사결정 도구가 된다. 단순 요약이 아니라 통합·번역·우선순위화가 이 단계의 본질이다.

## 입력 (모두 읽는다)

- `_workspace/tech_findings.md` — 기술 판단 + 기술→페이지 매핑 + 성능
- `_workspace/design_findings.md` — 팔레트 + 타이포 + 컴포넌트 + 디자인 톤
- `_workspace/content_findings.md` — IA + 콘텐츠 + CTA 흐름
- `00-summary.md` — 규모
- 필요 시 `05-components.md`, `07-performance-a11y.md` 원본 교차 참조

**세 발견 파일이 모두 준비되기 전에는 통합을 시작하지 않는다.** 하나가 끝내 누락되면 "❌ {영역} 누락"으로 표시하고 나머지로 진행.

## 작업 단계

### 1. 사이트 정체성 정의 (통합의 출발점)
세 영역을 한 문장으로 교차 종합한다. 예: "절제된 모노톤 팔레트(디자인) + 제품 중심 3-depth IA(콘텐츠) + Swiper 기반 비주얼 회전(기술)으로 '신뢰감 있는 B2B 제조사' 인상을 만든다." 이 문장이 모든 산출물의 앵커가 된다.

### 2. 유지 / 개선 / 도입 분류
세 영역의 발견을 의사결정 카테고리로 정렬:

| 분류 | 항목 | 영역 | 근거 |
|------|------|------|------|
| 유지 | 절제된 팔레트 | 디자인 | 브랜드 일관성 |
| 개선 | 모바일 LCP 4.2s | 기술 | 성능 저하 |
| 도입 | FAQ 페이지 | 콘텐츠 | 문의 부담 감소 |

### 3. 인사이트 우선순위화 (임팩트 × 난이도)
개선/도입 항목을 2축으로 정렬하여 "먼저 할 것"을 명확히. 빠른 성과(High임팩트·Low난이도)를 맨 위로.

### 4. 벤치마킹 레시피 (BENCHMARK_RECIPE.md의 핵심)
`tech_findings`의 기술→페이지 매핑을 **복제 레시피**로 변환한다. 각 핵심 기능은 메타(무엇을/어디서/사용기술) + **수신자별 2개 프롬프트**로 구성한다:

- **무엇을:** 복제할 기능 (예: "히어로 풀블리드 Swiper 캐러셀")
- **어디서:** 원본 페이지 경로 — **pages.json에 실재하는 경로만**
- **🎨 디자인 프롬프트 (시니어 디자이너용):** 섹션을 카테고리로 나누고, 각 카테고리에 들어갈 **실제 한글 콘텐츠**·위계·톤·인터랙션 위치를 자세히 서술. **모든 콘텐츠는 한글로 설계**하도록 명시.
- **⚙️ 인터랙션/개발 프롬프트 (전문 개발자용):** 라이브러리·트리거·타이밍·이징·반응형·접근성 구현 명세.

두 프롬프트는 같은 토큰(컬러·폰트)과 기능 묘사로 서로 호응해야 한 화면으로 합쳐진다.

> **⚠️ 인터랙션 내부 동작은 실측에 묶고, 없는 기능을 프롬프트에 지어 넣지 말 것.** 레시피·프롬프트에 적는 위젯 동작(진행바, 순차 분기, 상태머신, 결과 임계값, 문항 수)은 반드시 `09-runtime-interactions.md`의 **"자가진단 위젯" 실측**과 일치해야 한다. 실측에 `진행바 없음`이면 프롬프트에 진행바를 만들라고 쓰지 않는다. 실측이 없는 세부는 "원본 미확인 — 구현 시 확인 필요"로 표기하고, **결과 임계값처럼 추정으로 채운 값은 반드시 '추정'이라고 명시**한다(원본 톤과 다른 결과 카피를 단정하면 복제본이 어긋난다). 과거 실패: 검진설문에 없던 진행바·상태머신·임의 임계값(0~1/2~3/4~5)을 프롬프트 D에 박아 원본과 다른 UI를 유도함.

> 2-프롬프트 작성 형식·디자인/개발 프롬프트 품질 기준·좋은 예는 `references/recipe-format.md`를 **반드시 정독**하라.

### 5. 마스터 복제 프롬프트 (MASTER_REPLICATION_PROMPT.md)
BENCHMARK_RECIPE의 레시피 전체와 08/07 인사이트를 **하나의 자기완결 빌드 지시서**로 합친다. 이 문서 한 장만 다른 컴퓨터/AI에 던지면 사이트 전체를 near-clone으로 재현할 수 있어야 한다. 핵심:
- 단일 ` ```md ` 코드블록(=복붙 가능한 최종 프롬프트) + 검수 프롬프트 + 이미지 생성 프롬프트.
- **멀티 에이전트 역할 가이드**(프론트엔드/디자인시스템/인터랙션/콘텐츠/접근성·SEO·성능 QA)와 핸드오프 규칙을 반드시 포함 — 수신 AI가 역할별 전문 작업으로 분담하게.
- **레시피 13종 전수 흡수**(비교 테이블·아이콘 그리드·신뢰 배지 구조 누락 주의) + 08 우선 개선 선제 반영(모달→독립페이지·sticky CTA·모달 a11y) + 안전(법적) 치환(이미지·문장·신원·면책).

> 마스터 프롬프트의 골격·역할 가이드·레시피 매핑·자가점검은 `references/master-prompt-format.md`를 **반드시 정독**하라.

### 6. 한국어 리포트 작성
모든 산출물은 한국어, 기술 용어는 영문 유지(프로젝트 규약). 표·체크리스트·코드블록을 적극 활용.

## 출력 (output/{site}/ 에 작성)

### `08-renewal-insights.md`
사이트 정체성 → 유지/개선/도입 분류 표 → 우선순위 매겨진 개선 제안(임팩트×난이도).

### `BENCHMARK_RECIPE.md`
기술-페이지 매핑 표 → 각 핵심 기능별 복제 레시피(무엇을/어디서 + 🎨 디자인 프롬프트 + ⚙️ 개발 프롬프트). `references/recipe-format.md` 2-프롬프트 형식 준수.

### `MASTER_REPLICATION_PROMPT.md`
사이트 전체를 한 장으로 재현하는 자기완결 빌드 지시서(최종 프롬프트 + 멀티 에이전트 역할 가이드 + 검수 프롬프트 + 이미지 생성 프롬프트). `references/master-prompt-format.md` 골격 준수. 레시피 전수 흡수 + 안전 치환 필수.

### `COMPLETION_REPORT.md`
최종 종합 리포트. 구성: ① 요약(정체성 한 문장 + 규모) → ② 영역별 핵심 발견(기술/디자인/콘텐츠 각 3~5줄) → ③ 우선순위 인사이트 → ④ BENCHMARK_RECIPE·MASTER_REPLICATION_PROMPT 활용 안내 → ⑤ 전체 산출물 목록.

## 자가 점검 (출력 전)

- [ ] 사이트 정체성을 한 문장으로 정의했는가?
- [ ] 레시피의 모든 "어디서" 경로가 pages.json에 실재하는가?
- [ ] 각 레시피에 🎨 디자인 프롬프트 + ⚙️ 개발 프롬프트가 **둘 다** 붙어 있는가?
- [ ] 디자인 프롬프트가 카테고리별 **실제 한글 콘텐츠**를 채웠는가(플레이스홀더 아님)?
- [ ] 디자인/개발 프롬프트의 토큰·기능 묘사가 서로 호응하는가?
- [ ] **자가진단 위젯 동작(진행바·순차분기·상태머신·결과 임계값·문항수)이 `09-runtime-interactions.md` 실측과 일치하는가?** 실측에 없는 동작을 지어내지 않았고, 추정값은 '추정'으로 표기했는가?

- [ ] **마스터 프롬프트에 멀티 에이전트 역할 가이드 + 안전(법적) 치환 규칙이 들어갔는가?**
- [ ] 네 산출물 모두 한국어 + 기술용어 영문 규약을 지켰는가?
