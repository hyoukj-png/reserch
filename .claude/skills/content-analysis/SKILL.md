# 정보구조 & 콘텐츠 분석

수집된 사이트 구조와 페이지 본문을 읽고 **사이트가 무엇을 누구에게 어떤 순서로 전달하는가**를 해석한다. 핵심 산출은 synthesizer가 소비할 `_workspace/content_findings.md`다.

## 왜 이렇게 하는가

페이지 목록과 본문은 그 자체로는 의미 없는 데이터 더미다. 리뉴얼 의사결정에 필요한 건 "이 사이트는 3-depth 제품 중심 IA이고, 회사소개는 빈약하며, 모든 CTA가 '문의하기'로 수렴한다 → B2B 리드 확보가 목표"라는 **구조적 진단**이다. 목록을 IA로, 본문을 콘텐츠 전략으로 번역하는 것이 이 스킬의 일이다.

## 입력 읽기 순서

1. `00-summary.md` — 페이지/이미지 규모
2. `01-site-structure.md` — 전체 구조/계층 요약
3. `pages/_sitemap-tree.md` — 트리 형태 IA (depth 파악에 최적)
4. `04-content-inventory.md` — 페이지별 제목·미리보기·CTA
5. `pages/_index.md` + 주요 `pages/*.md` — 1차 내비/대표 랜딩은 전문 정독, 나머지는 제목·미리보기로 분류
6. `pages.json` — URL·depth·제목 메타(근거 데이터)

페이지가 50+면 대표 페이지 우선 정독, 나머지는 제목/미리보기 분류로 효율화. `pages/`가 없으면 04-content-inventory 미리보기만으로 분석하고 한계 명시.

> **⚠️ 빈약한 페이지는 "숨은 콘텐츠"를 의심하라.** 정적 수집은 `javascript:`/`onclick`으로 열리는 모달·탭 안의 텍스트를 못 가져온다. 어떤 페이지의 본문이 비정상적으로 짧으면(예: 39단어) 콘텐츠가 없는 게 아니라 **JS 트리거 뒤에 숨어 있을 가능성**이 높다. **먼저 `pages/_modals.md`를 읽어라** — 수집 스크립트가 모달/숨김 콘텐츠를 자동 복구해 여기에 저장한다. 있으면 **1차 콘텐츠 소스로 취급**하여 인벤토리·IA·밀도 평가에 포함하라(`00-summary.md`의 "숨김 모달 콘텐츠 블록" 수치로 존재 확인). 없는데 신호만 보이면 content_findings에 "모달/탭 콘텐츠 미수집 — 추가 수집 권장"을 명시하고, `_supplement/`에 수동 보충 HTML이 있으면 반영하라. 콘텐츠 밀도를 페이지 수가 아니라 실제 정보량으로 재평가한다.

## 분석 단계

### 1. IA 구조
페이지를 분류하고 계층을 그린다:

| 섹션 | 페이지 | depth | 비고 |
|------|--------|-------|------|
| 1차 내비 | 회사소개/제품/문의 | 1 | 메인 메뉴 |
| 제품 서브 | 제품 상세 N개 | 2~3 | 카탈로그 |
| 유틸리티 | 개인정보/이용약관 | 1 | 푸터 |

진단: depth 깊이, 메뉴 폭, IA 패턴(제품 중심/콘텐츠 중심/서비스 중심).

### 2. 콘텐츠 유형 & 밀도
섹션별 분량과 메시징 톤:

| 섹션 | 콘텐츠 유형 | 밀도 | 톤 |
|------|------------|------|-----|
| 회사소개 | 정적 소개 | 빈약 | 사실 나열 |
| 제품 | 스펙+이미지 | 풍부 | 기능 중심 |

카피가 기능 중심인지 감성 중심인지, 본문이 충실한지 껍데기인지 판단.

### 3. CTA & 전환 흐름
04-content-inventory의 CTA 버튼을 모아 분석: 어떤 행동(문의/구매/구독)을 유도하며, 어디에 배치되는가. CTA가 한 곳으로 수렴하는지 분산되는지 → 사이트의 비즈니스 목표 추론.

### 4. 리뉴얼 진단
- **누락:** 있어야 하는데 없는 페이지 유형(FAQ, 사례, 블로그 등)
- **노후/중복:** 오래되거나 겹치는 콘텐츠
- **IA 개선 여지:** 너무 깊은 depth, 모호한 메뉴명, 고아 페이지

## 출력: `_workspace/content_findings.md`

```markdown
# 콘텐츠 발견 (content_findings)
## 1. IA 구조 {섹션 분류 + depth 표 + 진단}
## 2. 콘텐츠 유형/밀도 {표}
## 3. CTA & 전환 흐름 {수렴 분석 + 비즈니스 목표 추론}
## 4. 콘텐츠 강점/약점 {누락·노후·개선 여지}
```

## 자가 점검 (출력 전)

- [ ] IA에 언급한 모든 페이지가 pages.json/sitemap-tree에서 확인되는가?
- [ ] CTA 흐름에서 비즈니스 목표를 추론했는가?
- [ ] 누락된 콘텐츠 유형을 짚었는가?
- [ ] 페이지가 많을 때 대표 페이지를 실제로 정독했는가?
